# Grievances — ledger of non-blocking findings

> Committed register of underlying problems, technical debt and improvements met
> **outside the scope of an in-flight spec**: "what works, but will not scale, or
> only holds together with tape". Committed on purpose — friction should
> accumulate visibly.
>
> **This file is maintained programmatically.** Declare and close entries with the
> `grievances` skill CLI; never hand-edit the index tables below:
>
> ```bash
> grievances.py add --short "..." --severity high --locus "file.go:42" \
>   --finding "..." --impact "..." --fix "..." --effort 0.5d
> grievances.py resolve GRV-0001 --commit 1a2b3c4 --note "..."
> ```
>
> Prose under `# Details` is human-owned and kept verbatim; the heading lines, the
> `<!-- grievance:... -->` markers and both tables belong to the tool, which
> re-sorts them chronologically on every mutation.
>
> **Boundary.** Anything regulatory, security-related, data-losing or needing an
> arbitration does NOT stay here: it becomes a spec, or a fiche in the pilot
> `ROADMAP.md`, immediately — close the grievance with `--promoted-to <ref>` so a
> one-line pointer remains and the analysis lives in exactly one artifact.
>
> Never paste a secret, a token or a credential-bearing log line into an entry:
> record the *command* that retrieves a credential, never its value.
>
> When to read and when to write: `specs/CLAUDE.md`.

<a id="grv-0002"></a>
### GRV-0002 · medium · 2026-08-19 — reverse-graph targets are never filtered by the context include/exclude patterns

`src/core/impact.ts:205-213` · declared in adversarial review, openai/gpt-5.6-sol, spec 004

<!-- grievance:GRV-0002:prose -->

**Finding.** collectFiles() applies matchesContextPatterns() to importers, but resolveInternalImports() registers every resolved target without it — matchesContextPatterns is reachable only from collectFiles (impact.ts:241). An explicitly excluded file therefore still owns a reverse-graph key and still gets an answer. Importers always come from the filtered set, so an excluded file can never appear AS a dependent; only the queried target is affected. Pre-existing in shape, but the package-widening turns one out-of-scope key per package into N.

**Impact.** A caller who scopes a run with --exclude gets an answer for a file they excluded, so the exclusion does not mean what its name says. Low blast radius today; the ambiguity is what makes it worth recording rather than the damage.

**Fix.** Decide the contract first: either an explicitly named target overrides the exclusion (document it), or filter targets in resolveInternalImports. **Effort: 2h.**

<!-- /grievance:GRV-0002 -->

### GRV-0003 · low · 2026-08-19 — package-granular reverse edges scale as importers x package size

`src/core/impact.ts:88-99` · declared in adversarial review, openai/gpt-5.6-sol, spec 004

<!-- grievance:GRV-0003:prose -->

**Finding.** Each import now registers one Set.add per file of the imported package. For 1900 importers of a 90-file package that is ~171000 registrations instead of 1900. packageFilesCache removes the repeated readdirSync but not the edge fan-out, which is inherent to package-granular semantics. Measured during spec 004: +0.4%/+9% on realistic inputs, +111% on an adversarial one.

**Impact.** The cost is correct and unavoidable given the semantics, but it is undocumented, so the next person to meet a slow run on a huge monorepo will hunt for a regression that is not there.

**Fix.** Document the scaling law in the Go section of the README next to the granularity note. **Effort: 30m.**

### GRV-0004 · medium · 2026-08-19 — _isInVendorOrCache matches the whole absolute path, not the module-relative one

`src/core/go-mod.ts:299-302` · declared in spec 004 review

<!-- grievance:GRV-0004:prose -->

**Finding.** _isInVendorOrCache splits the full absolute filePath and tests every segment for 'vendor' or '.gomodcache'. A repository checked out under any directory named vendor — /srv/vendor/app, for instance — matches on the checkout prefix, so every .go file of every package is filtered out. Character-identical at HEAD, so pre-existing.

**Impact.** The reader gets a confident '0 dependent(s)' for an entire repository — the same failure mode spec 004 exists to repair, one parent-directory name away.

**Fix.** Match against the module-relative path, not the absolute one. **Effort: 1h.**

### GRV-0005 · medium · 2026-08-19 — PathResolver.matchGlob escapes '.' after expanding globstars, so '**' matches only dots

`src/core/resolver.ts:439-449` · declared in spec 004 review

<!-- grievance:GRV-0005:prose -->

**Finding.** The replace chain expands ** to .* and only then runs .replace(/\./g,'\\.'), re-escaping the dot it just inserted. '**/node_modules/**' compiles to a pattern meaning 'zero or more literal dots'. src/core/impact.ts:289-296 already ships a second, correct copy whose comment names the bug.

**Impact.** Two glob engines with divergent semantics live in one package. PathResolver.matchesPatterns silently mis-filters include/exclude, and the next caller reaching for it will not read the warning comment 200 lines away.

**Fix.** Delete the broken copy and export the correct one from a single module. **Effort: 2h.**
